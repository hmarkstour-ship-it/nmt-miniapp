# НМТ Математика — Telegram Mini App

Міні-застосунок, який генерує завдання з математики для підготовки до НМТ
через безкоштовний Gemini API, з автоматичною самоперевіркою правильності
відповіді, збереженням прогресу в базі даних і захистом від повторів завдань.

## Локальний запуск

### 1. Встанови залежності

```bash
npm install
```

### 2. Створи безкоштовну базу даних (Supabase)

Потрібна для збереження прогресу між сесіями і щоб AI не повторював одні й ті самі завдання.

1. Зайди на https://supabase.com → Start your project → зареєструйся
2. Створи новий проєкт (New Project), задай будь-який пароль для бази — **збережи його**
3. Зачекай ~1-2 хвилини, поки проєкт піднімається
4. Зайди в **Project Settings → Database → Connection string**
5. Обери режим **Transaction pooler** (важливо саме цей, не Session)
6. Скопіюй рядок виду `postgresql://postgres.xxxx:[YOUR-PASSWORD]@...`
7. Встав туди свій пароль з кроку 2 замість `[YOUR-PASSWORD]`

Таблиці створювати вручну не треба — сервер сам створить їх при першому запуску
(дивись `initDb()` у `server.js`).

⚠️ **Безкоштовний проєкт Supabase "засинає" після 7 днів без жодного запиту.**
Дані при цьому не губляться, просто треба буде зайти в панель Supabase і
натиснути "Restore project".

### 3. Отримай безкоштовний ключ Gemini API

1. Зайди на https://aistudio.google.com/apikey
2. Створи ключ (карта не потрібна)

### 4. Заповни .env

```bash
cp .env.example .env
```

Відкрий `.env` і заповни всі три значення:

```
GEMINI_API_KEY=твій_ключ_з_кроку_3
BOT_TOKEN=токен_від_BotFather
DATABASE_URL=рядок_підключення_з_кроку_2
```

`BOT_TOKEN` — той самий, що видав @BotFather при `/newbot`. Без нього прогрес
не прив'язується до конкретного користувача (застосунок працюватиме, але без
збереження статистики).

### 5. Запусти сервер

```bash
npm start
```

Відкрий `http://localhost:3000` у браузері — маєш побачити застосунок.

### 6. HTTPS для тестування (ngrok)

```bash
ngrok http 3000
```

Отримаєш посилання виду `https://xxxx.ngrok-free.app` — встав його в
BotFather (`/mybots` → бот → Bot Settings → Menu Button).

## Постійний хостинг (без ngrok) — Render

ngrok підходить лише для тестування: посилання змінюється щоразу і сервер
живе лише поки увімкнений твій комп'ютер. Для постійної роботи:

1. Заведи акаунт на https://render.com (можна через GitHub)
2. Заливи код проєкту на GitHub (окремий репозиторій)
3. У Render: **New → Web Service** → підключи свій GitHub-репозиторій
4. Налаштування:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Instance Type:** Free
5. У розділі **Environment** додай ті самі змінні, що й у `.env`:
   `GEMINI_API_KEY`, `BOT_TOKEN`, `DATABASE_URL`
6. Натисни **Create Web Service** — Render видасть постійне посилання виду
   `https://твій-застосунок.onrender.com`
7. Встав це посилання в BotFather (Menu Button) один раз — більше міняти не
   доведеться

⚠️ **Особливості безкоштовного тарифу Render:**
- Сервіс "засинає" після 15 хвилин без запитів і "прокидається" ~30-60
  секунд при наступному запиті — перше відкриття застосунку після паузи буде
  повільним, це нормально
- База даних окремо на Supabase — тому навіть якщо Render перезапустить
  сервіс, прогрес користувачів не зникне

## Як це працює

- `POST /api/generate-question` — перевіряє, хто користувач (`initData`),
  підтягує з бази його останні завдання з цієї теми, просить Gemini
  згенерувати нове (з інструкцією уникати повторів), перевіряє правильність
  другим викликом, зберігає в історію
- `POST /api/answer` — записує правильну/неправильну відповідь у базу
- `POST /api/progress` — повертає збережену статистику при відкритті застосунку
- Обидва виклики до Gemini мають тайм-аут (25с) і до 3 повторних спроб при
  тимчасових помилках (429/503) з наростаючою затримкою
- Фронтенд (`public/index.html`) — чистий HTML/CSS/JS з Telegram Web App SDK,
  без збірки, без фреймворків

## Що варто додати далі

- **Кешування** згенерованих завдань у базі — зараз кожен запит витрачає
  виклик до Gemini, навіть якщо схоже завдання вже колись генерувалось для
  когось іншого
- **Інші предмети** — структура `TOPICS` і промпти легко клонуються під
  українську мову, історію тощо
- **Статистика по темах** — зараз рахуються лише загальні ✅/❌, а не в розрізі
  тем, хоча вся історія вже зберігається в `question_history`
